# WB Order Drop Bot

Telegram-бот для ежедневного поиска падения заказов по артикулам продавца Wildberries.

## Что делает

- работает с двумя кабинетами WB отдельно;
- берёт **заказы**, а не выкупы/продажи;
- считает FBO + FBS вместе;
- отменённые заказы **не исключает**;
- объединяет строки по `supplierArticle` (артикулу продавца), поэтому несколько баркодов одного артикула суммируются;
- среднее = заказы за 14 полных дней, предшествующих вчерашнему дню / 14;
- сравнивает со вчерашним днём;
- по умолчанию сообщает о падении **более 15%**;
- если вчера 0 заказов, товар попадает в отчёт как падение 100%;
- в Telegram показывает до 20 строк;
- полный список отправляет в Excel;
- если падений нет, отправляет короткое подтверждение;
- ежедневный запуск по умолчанию в 10:00 МСК;
- есть ручная кнопка «Проверить сейчас»;
- настройки каждого пользователя хранятся в SQLite.

## Меню

- 📊 Проверить сейчас
- 📉 Порог: 10 / 15 / 20 / 25 / 30 / 50%
- 📋 Сортировка:
  - по проценту падения;
  - по среднему числу заказов;
  - по абсолютному снижению.
- 🕙 Время уведомлений
- 🏢 СПб-ТТ / СПБ-ТТ ГРУПП / оба

## WB API

Используется Statistics API:

`GET https://statistics-api.wildberries.ru/api/v1/supplier/orders`

Нужен токен WB с категорией **Статистика**.

Бот делает один основной запрос на кабинет за анализируемый диапазон и затем
группирует полученные строки локально. Это важно из-за низкого лимита
Statistics API.

API WB обновляет данные заказов не мгновенно, поэтому утренний отчёт отражает
состояние данных, доступное WB к моменту запуска.

## Установка на VPS / bothost

1. Загрузить файлы проекта.
2. Создать `.env` из `.env.example`.
3. Заполнить:
   - `TELEGRAM_BOT_TOKEN`
   - `ALLOWED_TELEGRAM_IDS`
   - `WB_TOKEN_SPB_TT`
   - `WB_TOKEN_SPB_TT_GROUP`
4. Установить Python 3.11+.
5. Установить зависимости:

```bash
pip install -r requirements.txt
```

6. Запустить:

```bash
python bot.py
```

## Docker

```bash
docker build -t wb-order-drop-bot .
docker run -d --restart unless-stopped   --name wb-order-drop-bot   --env-file .env   -v $(pwd)/data:/app/data   wb-order-drop-bot
```

## Важный момент про Telegram

Даже если Telegram ID находится в белом списке, бот обычно не может первым
начать личный диалог с пользователем. Каждый пользователь должен один раз
открыть бота и нажать `/start`.

## Формула

Пример:

- за 14 базовых дней: 280 заказов;
- среднее: 20 заказов/день;
- вчера: 12;
- падение: `(20 - 12) / 20 * 100 = 40%`.

При пороге 15% товар попадёт в отчёт.

## Примечание по истории заказов

Statistics API гарантирует ограниченный период хранения оперативных данных.
Для этого бота достаточно 15 анализируемых дней.

В проекте используется `flag=0` и затем локальная фильтрация по дате заказа.
Так бот избегает необходимости делать отдельный WB-запрос на каждый из 15 дней.


## Цена и остатки в Excel

В итоговый Excel дополнительно выводятся:

- средние заказы/день за первые 7 и последние 7 дней базового периода;
- изменение заказов между этими половинами периода, %;
- средняя цена заказа (`priceWithDisc`) за первые 7 и последние 7 дней;
- изменение цены, %;
- средняя цена вчера;
- остаток FBO и FBS на вчерашний день, если доступен отчёт `STOCK_HISTORY_DAILY_CSV`.

Для исторических остатков нужен токен категории **Аналитика**. Можно заполнить
`WB_ANALYTICS_TOKEN_SPB_TT` и `WB_ANALYTICS_TOKEN_SPB_TT_GROUP`. Если они пустые,
бот попробует использовать основной токен кабинета. Если прав на Аналитику нет,
бот всё равно сформирует отчёт, а колонки остатков останутся пустыми.

## Расширенная диагностика падения заказов

Для товаров, попавших в отчёт, бот дополнительно пытается получить:

- изменение фактической цены заказа: первые 7 дней против последних 7 дней;
- остаток FBO и FBS на вчера;
- просмотры карточки товара;
- добавления в корзину;
- конверсию просмотр → корзина;
- конверсию корзина → заказ;
- добавления в избранное;
- среднюю позицию товара в поиске за первые и последние 7 дней.

Воронка берётся из актуального `POST /api/analytics/v3/sales-funnel/products/history`.
Дневная история этого метода ограничена 7 днями, поэтому бот запрашивает два периода по 7 дней.

Поисковые показатели опциональны: часть Search Analytics API может требовать подписку «Джем».
Если доступа нет, соответствующие ячейки Excel остаются пустыми, основной отчёт продолжает работать.

Для дополнительных показателей нужны токены категории «Аналитика»:
`WB_ANALYTICS_TOKEN_SPB_TT` и `WB_ANALYTICS_TOKEN_SPB_TT_GROUP`.

Из-за лимитов WB Analytics расширенный отчёт может формироваться заметно дольше базового.
