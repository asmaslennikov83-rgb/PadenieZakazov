# Исправление 3.0.1 после проверки рабочего архива

В архиве WB_аналитика_2026-10-19_v3.0.0_r1.zip отчёт сформирован через 40,995 секунды после начала первой загрузки. Уже получены данные заказов, но не получено подтверждение окончания пагинации. Обнаружено ошибочное отображение нулевых счётчиков SourceStatus во время загрузки; дополнительных запросов на момент среза ещё не было.

## Исправления

- Метаданные заказов/продаж сохраняются после каждой страницы: видны количество страниц, строк, курсор, время обновления и этап. Строки — число полученных строк API, не обязательно число уникальных единиц.
- Очередь дополнительных источников видна с начала полного прохода: QUEUED означает «запрос ещё не начат», а не отсутствие прав. RUNNING/FINISHED/FAILED/INTERRUPTED позволяют различить ход и результат.
- Каталог, цены, остатки и воронка запускаются раньше длительной загрузки продаж. Источники по-прежнему выполняются независимо по результату; ошибка одного не выдаётся за нули другого.
- Кэш отчёта учитывает изменения источников; завершение основной загрузки не скрывается старым результатом ещё на две минуты. Старые кэши пользователя удаляются.
- При первой загрузке Telegram явно объясняет неизвестный итог и прогресс. Во время очередного обновления ранее подтверждённый срез сохраняется с пометкой, что обновление ещё не закончено. При завершившейся ошибке он по-прежнему помечается устаревшим.
- Добавлены кнопка «Обновить данные» и команда /refresh для полного прохода, включая дополнительные источники. Активная фоновая загрузка не дублируется.
- При запуске под блокировкой единственного процесса восстанавливаются статусы прерванных загрузок и снимаются оставшиеся блокировки синхронизации; это устраняет задержку до 30 минут после аварийного перезапуска. Порядок старых/новых статусов не меняется.
- Смена версии отчёта создаёт отдельную ревизию; сохранённый старый пакет не подменяется новым определением.

## Установка поверх 3.0.0

1. Остановить бота на Bothost, сохранить текущий код, всю data и настройки окружения.
2. Заменить файлы кодом из полного архива 3.0.1. Сохранить рабочую data/bot.db, report_snapshots и прежние токены/пути. Удалять базу и загружать 90 дней с нуля не нужно.
3. Запустить один экземпляр. Новая схема БД не требуется: сохранена схема 3, миграции предыдущей версии остаются идемпотентными.
4. Сразу после запуска /quality может показывать очередь. После завершения orders должно быть FINISHED/OK и покрытие основного сравнения 15/15, если API действительно завершил полную выгрузку нужного интервала.
5. Запросить /overview, затем /excel. Для дополнительных источников дождаться FINISHED или явной ошибки; /refresh запускает полный проход вне расписания. Не нажимать повторно, пока идёт проход.
6. Если источник завершился с NO_ACCESS/401/403 — проверить категорию токена. ERROR/429 означает ограничение запросов; PARTIAL с курсором означает продолжение. Не превращать эти состояния в нули.

Права Аналитики по исходному архиву не установлены: нужных попыток запросов ещё не было. Эта сборка подготовлена локально; на вашем хостинге изменения не применены. Реальные ответы после завершения полного прохода ещё нужны для проверки контрактов дополнительных адаптеров.
